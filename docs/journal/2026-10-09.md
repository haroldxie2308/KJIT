## 00:04 +0800 — Worktree tooling fixes

Commit: 9c4bd89

Four tooling bugs hit while running A11 from git worktrees, each reproduced and
fixed at its cause (agent report, audited):

- `scripts/docker-dev.sh`: a worktree's `.git` file points at
  `<main>/.git/worktrees/<name>`, outside the `/workspace` mount, so every git
  call in the container failed (exit 128). Fix: mount the git common dir at its
  host path. Verified from a worktree and (by me) from the main checkout.
- `scripts/guest-run.sh`: the QMP socket under a deep build root exceeded the
  104-byte unix socket path limit on macOS. Fix: a private `mktemp -d` socket
  dir per run; `require_unix_socket_path` fails fast on any path still too
  long. Verified: `make guest-run` from a worktree without a symlink.
- `make guest-run CMD=...`: `$(CMD)` was pasted into the recipe, so double
  quotes broke it; now `$$CMD`. Remaining limit: make still expands `$` on its
  command line (write `$$` or pass CMD through the environment).
- `scripts/mk-guest-rootfs.sh`: Docker Desktop resolved a scratch dir that was
  deleted and recreated at the same path to the deleted one (`/out/<test>: No
  such file`, 3 of 8 back-to-back runs; a 30-iteration mount experiment failed
  24/30 with path reuse, 0/30 with fresh paths). Fix: a fresh `mktemp -d` work
  dir per run. Verified: 15/15 back-to-back `guest-rootfs`, 8/8
  `guest-rootfs` + `guest-run`.
- Not run after the cherry-pick onto A11: the guest suites (scripts only).

## 00:47 +0800 — Dispatch-table miss classification

Commit: ef6f971

Question: after A11 every `ibtc_insert` was an `ibtc_replace` under
redis-benchmark. Are the BL/BLR/BR/RET exits that still reach the runtime
cold misses, conflict misses (direct-mapped aliasing) or something else; are
conflicts concentrated (aliasing) or spread (capacity); call targets or return
sites?

Method: the runtime classifies each branch exit against the run's own table
slot before publishing (`runtime/ibtc.rs`): cold (empty), conflict (another
pc's record), other (same pc, only through a racing publish); non-FP -> FP
exits (`ibtc_fpsimd_boundary`) are excluded. Per-slot conflict counts per table
class with the last evicting/evicted pc in debugfs `ibtc_slots` (`reset` zeroes
them). `tests/guest/a11-baseline.sh` resets/dumps them per run and prints the
server's `/proc/<pid>/maps`; pcs mapped to symbols with `llvm-nm` on the
binaries from the rootfs. Points `off` and `chain_budget` 1024, 3 passes of
`-t set` and `-t get` x 200000 requests, fresh server per boot, 2 boots
(orders `off 1024`, `1024 off`), kjit-guest, M1/HVF, 4 vCPUs, host load ~4-5.

Commands: `./scripts/docker-dev.sh --no-tty -- make module-build
KJIT_KERNEL_PROFILE=kjit-guest`; `make guest-rootfs`; `./scripts/guest-run.sh
--profile kjit-guest --run-dir <runs>/a38-miss-boot{1,2} --timeout 2400 --
'set -- /tmp/a11 3 200000 off 1024; . /opt/kjit-tests/a11-baseline.sh'`.
Gates: `make guest-tests`, `make guest-tests-k3` ALL PASS.

Raw data: serial logs `runs/a38-miss-boot1`, `a38-miss-boot2`, `a38-ab` under
the build root of worktree agent-ac3b24e86f29900e2; copies and analysis
scripts in the session scratchpad (not kept in the repo).

Results (per request, chain_budget 1024, mean of 6 runs; identity
cold + conflict + other + boundary == branch exits held in all 24 runs):

| test | req/s | runtime entries | cold | conflict | other | FP/SIMD boundary |
|---|---|---|---|---|---|---|
| SET | 115953 (100251..130124) | 28.51 | 0.018 | 18.49 | 0 | 7.98 |
| GET | 136615 (121803..154202) | 15.93 | 0.004 | 8.83 | 0 | 5.05 |

KJIT off: SET 223783, GET 223459 req/s (mean of 6). Conflicts sit in 5-17
slots per table; the top 8 slots hold 94-100%. Nearly every hot slot is a
two-pc ping-pong between redis functions 16 KiB apart, e.g.
`processCommand+0xfc` (return site) / `string2ll`, `counts_index_for+0x14` /
`keyIsExpired`, `zmalloc` / `call`, `je_malloc` / `dbOverwrite`. Function
entries and return sites both appear (SET: ~10.2 vs ~8.4 conflicts per
request).

Conclusion: beyond the by-design FP/SIMD boundary, misses are almost entirely
conflict misses from a handful of aliasing pairs; capacity and cold misses are
negligible. The table is not too small but direct-mapped on `pc[13:2]`.
Removing the conflicts would leave about 10 runtime entries per SET request
and 7 per GET (inferred, not measured).

Caveats: no hit counter (no hit rate); per-slot counters are global across
mms; libc symbols are dynsym-approximate; debug profile not run; host varied
~15% between boots; the instrumentation's own cost was not resolvable
(A/B medians -2.2% SET, -0.1% GET within +-15% noise).

## 00:56 +0800 — FP/SIMD bracket: core problem and the experiments launched

Commit: none (discussion; experiments in progress)

- Core problem: fragments use the user's V0-V31/FPCR/FPSR live in hardware.
  arm64 Linux saves them lazily (only at context switch or kernel-mode NEON,
  restored on return to userspace), so the registers are guaranteed to be the
  task's only while preemption and softirqs are off: hence the
  `local_bh_disable` bracket, and `pagefault_disable` because it is atomic.
  Before A11 the bracket ended at the FP/SIMD fragment's first exit; since A11
  a bracketed run dispatches through `table_all` into integer code, so the
  non-preemptible stretch is a whole run (see 2026-10-05, review finding).
  Cutting it per fragment instead costs ~8 runtime entries per SET request
  (the `ibtc_fpsimd_boundary`).
- Hypothesis under test: this kernel's task-level `kernel_neon_begin(state)`
  (TIF_KERNEL_FPSTATE, state saved/restored at context switch) allows a
  preemptible bracket: load the user state into the registers, run, store it
  back. Experiment (prototype, variants A = latency only, B = one table)
  delegated; pagefault_disable kept in v1 to avoid nested task-level NEON in
  fault paths.
- Dispatch-table conflicts: three variants (index hash, 2-way sets, victim
  table) delegated as a measured prototype experiment.

Conclusion: V3a (+2 KiB per table, main-slot hit identical to V0) and V2b
(doubled memory, no conflicts per set) both remove the conflict misses and
reach 0.61-0.62 (SET) / 0.68-0.70 (GET) of KJIT off, from 0.49 / 0.60;
their difference is within the per-cell spread. V1 and V2a alone are not
enough. V3 is not collision-proof (two evicted pcs may share a victim slot;
expected ~0.25 hot collisions per boot offline, none in 12 boots); V2b is the
structurally robust one. Decision pending; adopting either is a contract change
(template, verifier internal miss edges, publish/retire policy).
