### Decision not in the contract: the alias is unmapped, not read-only

The contract says the helper makes the alias read-only. No in-tree entry point does that for this block: `change_memory_common()` is the
only route to a read-only linear alias (`set_memory_ro` -> `__change_memory_common` on `area->pages[idx]`) and it refuses
`VM_ALLOW_HUGE_VMAP` areas; `__change_memory_common()` is static in `pageattr.c`. Making it callable means a new export or a new function
in `arch/arm64/mm/` (a contract change in mm). `set_direct_map_valid_noflush(page, nr, false)` exists for exactly this, one call for the
512 pages (it flushes the TLB range itself on arm64), and `vm_reset_perms()` already passes through that state on every
VM_FLUSH_RESET_PERMS free (`set_direct_map_invalid_noflush`, flush, `set_direct_map_default_noflush`), so the free path restores it with no
extra code. A write through the alias faults either way (W^X holds); a read faults too, where A17's chunk alias stays readable. Nothing
legitimate reads the alias of vmalloc memory. Proposed contract edit: "Linear alias: ... the helper unmaps the linear alias of every page
(read and write fault; `set_direct_map_valid_noflush`) before it returns the block"; same wording in patch list item 10 ("an unmapped
linear alias under `rodata=full`"). If read-only is wanted, it is an extra mm patch.

### Contract issues found (all three resolved below: 1 by the entry labels of main 42ee64a, 2 by its reworded invariant)

1. **A20's "block start" is not the only entry to a block.** Every original PC of a fragment has a `vlabel`, and all of them are published as dispatch records (`kjit_ibtc_publish`), link targets
   (A16 label hash) and `kjit_frag_link` targets, so an indirect branch, a tail call or a `bl` whose target PC is in the middle of another block lands mid-block, after the check the dedup elided.
   If user SP is misaligned there, native takes SIGBUS and the fragment does not. Reproduced: `midblock_probe.s` (`br x9` to a label after `ldr x0, [sp]`, `sub sp, sp, #8` before it) fails the harness
   differential on this tree ("original vs fragment state mismatch"). It needs a program that faults natively, and an entry at a PC no static branch of the fragment names (switch targets, longjmp,
   computed jumps, function middles), so it is rare, but the contract says "exact". Proposed fix: labels used as dispatch, link and `kjit_frag_link` targets are the fragment entry and the block starts only
   (`ExecutionFragment` gains the list; `code_cache` and `runtime/translate.rs` build their labels from it; `vlabels` stays for the harness trace and branch resolution). A mid-block target then misses and
   translates its own fragment (more code, no new hazard); then the dedup is exact by construction. Cost to measure: `translate_ok` per redis request. Alternative: drop the dedup across original
   instructions that are not block starts of every possible entry (no gain left).
2. Section "Unsupported-instruction exit" states the invariant "reg-virt rewrites each original instruction independently of its neighbours". After A20 only admission and scratch use are independent; the
   presence of the SP check depends on the block. Proposed text: "whether an instruction can be lowered, and with which scratch, is independent of its neighbours; only the presence of the SP alignment check
   (A20) depends on the block, and never changes either".
3. Rule 10 as written lets a write of x13 before the slot (in the link write's part of the guarded run) pass: it is overwritten by the `movz` and x13 is dead at a linked target, so it is harmless; tested as accepted.

### What was built (branch `exp/ret-cont`, base dc1b962, uncommitted)

Every change is marked EXPERIMENT in the code; `shared/trans/retcont.rs` is the switch (mode 0 = today, 1 = (1), 2 = (1)+(2)); the
kernel module sets it through debugfs `retcont` (KJIT disabled; the write drops every fragment of every mm and waits for them to retire),
tests per thread (`retcont::with_mode`, default `$KJIT_RETCONT`). Mode 0 emits the same code as main except for the ABI change below.

**(1) Return continuations** (`cfg.rs`): a `BL`/`BLR` block gets its resume pc as successor, as an `SVC` block has. The continuation is a
block nothing falls into (the call's lowering ends in a branch) and only a return enters; layout puts it right after the call, every body PC is
already an entry label (`vlabels` -> kernel entries -> verifier rule 4), so rule 4 and the kernel accept it unchanged. Kernel side
(`kjit_lookup_label`, `exec.rs`): a `RET` exit whose target is no fragment's entry but a label inside some fragment is continued there
and published in the dispatch tables (counter `ret_label`); without it the profiler would learn a second fragment for every return point,
which is the f2 of 10-12 02:04, and (1) would change nothing but fragment layout. Only `RET` exits use the label lookup.

**(2) The shadow return ring** (`abi/frame.rs`, `abi/wrapper.rs`, `rephrase.rs`, `layout.rs`, `verify/mod.rs`):

```text
ring: 16 entries of { u64 user resume pc; u64 host address }, in the runtime frame at [208, 464),
      direct-mapped by user sp[7:4] (physical x17), cleared by the prologue (16 `stp xzr, xzr`).
BL / BLR, after the link write (x30 = resume pc), before the link slot:       5 words
  ubfx x14, x17, #4, #4                    ; ring index of the user sp
  add  x12, sp, x14, lsl #4                ; &ring[index] - 208
  adr  x14, <continuation label>           ; host: a verified entry offset of this fragment
  stp  x30, x14, [x12, #208]               ; { resume pc, host }
  movz x14, #0                             ; x14 is no kernel value on the linked `b` out of the slot
RET:  sub x18 / cbz x18 (budget, as before), then                              10 words on a hit
  orr  x13, xzr, xN                        ; T, as before
  ubfx x14, x17, #4, #4 ; add x12, sp, x14, lsl #4
  ldp  x14, x12, [x12, #208]               ; { pc, host } of the entry
  sub  x14, x14, x13 ; cbnz x14, 1f        ; the entry's pc is T
  cbz  x12, 1f                             ; empty entry (0, 0) must not match T = 0
  br   x12
1: sub x18 ; cbz x18 ; <dispatch template>  ; second budget check + today's path on a miss
```

Keyed by the user sp, not by a top-of-stack index: a TOP slot would chain every call and return through one store-to-load forward in memory
(no register is free: x12-x15 are the reg-virt scratch pool, x18 the budget, x16/x17 the mapped x29/sp) and a ring entry needs no pop. The key only
has to find the entry the matching call wrote: the callee restores sp, so the return sees the sp of the call. A wrong entry is only a miss.

*ABI cost (frame variant, what was built):* the frame grows from 208 to 464 bytes (kernel stack, 16 KiB), the prologue grows by 16 words
(0xa8 -> 0xe8 bytes) and clears 256 bytes on every fragment call whatever the mode (about 3 fragment calls per redis request: +49 words
per request), every fragment's bytes change (prologue, epilogue offset, `stp x29, x30, [sp, #-464]!`), the K0 golden is regenerated,
and the ring mode 2 / mode 0 pairing in one boot needs one prologue for both (the cost of the zeroing is therefore in m0, m1 and m2
alike). The alternative that keeps the frame: a ring in the extra-params block (zeroed by the runtime in mode 2 only), reached through
the saved extra pointer (frame slot 184, a new body-readable slot): +1 load word per push and per pop (+317 words per request), no prologue
change. I built the first because it is the lower word count.

*Verifier* (`verify/mod.rs`, new `VerifyRule::RingGroup`): the push and the pop are byte-exact groups like the dispatch template
(`ring_push_matches` up to the `adr` immediate, `ring_pop_matches`). Rules: the push's `adr` target is an entry offset; no join point
inside a group; the pop is guarded by the budget check (the `sub; cbz` pair before its target move, as a template is); the dataflow
steps are hand-written (`step_ring_push`: x12 becomes a frame address, x14 a host and is zero after the group; `step_ring_pop`: T must
not be a kernel value, the two miss branches and the `br x12` carry only x12). Everything else is the existing rules: any other access
to frame bytes `[208, 464)` is `FrameAccessOutOfRange`, any other base register `RuntimeAccessBase`, any other `adr` `PcRelative`, any other
`br x12` `IndirectBranch`/`DispatchTemplate`.

*Invariant the pop's `br x12` rests on:* the ring is frame memory; only the prologue (byte-exact, zeroes) and the push groups write it,
only the pop groups read it, nothing else of the body can reach it (rules 3 and 9 above, checked by the mutation suite); the push stores
`adr` of an entry offset of its own image, so every non-zero host word is `image + a verified entry offset`; the pop branches to it
only when it is non-zero and the entry's pc word equals T. The image is alive: the fragment that wrote the word ran in this fragment
call, and a fragment found or entered in a hook call stays allocated until that call returns (docs/pipeline.md section 8, hook SRCU), a
retirement during the call only lets the run go on in code that was valid when it started, as a linked `b` or a loaded slot does. The
class rule holds because the writer ran in this call: a call outside the FP/SIMD bracket never ran FP/SIMD code, so its ring has no host in
one. A host written for the wrong pc is not a safety issue (it is an entry of the same image) but an exactness one: the pairing of the
`adr` target with the pc in x30 is the translator's. *A product rule* must prove it: the verifier gets `(offset, pc)` for the entries (the
kernel has them in `kjit_entry`), recovers the `movz`/`movk` constants of the link write the way rule 10 recovers the link target, and requires
`pc(adr target) == resume constant`. That is one more input table and one more walk back from the group, and it removes the translator from the
exactness argument. Not done here.

*Budget:* a ring hit is charged by the first check (a loop of ring returns has no other charge: without it `ret` to a stale entry with the same
x30 and sp would loop in the kernel for ever), a miss is charged twice (the second check guards the template as before). Budget units therefore
count RET misses: units(m2) - units(m1) = misses (the units build below).

### Conclusion

- (2) is a loss of about 0.06 us per request in every cell measured (6 of 6 pooled positive, TCP GET significantly), explained by its word count: 5 words per call against 2 saved per hit return, 9 more per miss, a 93%
  hit rate because the ring is emptied at every fragment call, and 16 words of clearing per call. Its hit path's shorter load chain (one load instead of four) is not visible: the push-only ablation puts the cost in the pushes and nothing back in the pops.
  A hit still ends in an indirect `br` and the pair never reaches the RAS; whether that matters was not measured (no PMU in the guest).
- (1) alone does not pay either: -0.010 us pooled, no cell significantly below zero except TCP GET (-0.040, CI upper -0.003), more FP/SIMD transitions (+0.10 to +0.36 per request), twice the code, K2 `fork_cow` fails
  its Mem-exit check. Its structural effect (half the fragments, the return point no longer a fragment of its own) is real; its time effect is within the noise of this host.
- The hot-path cost of a RET (12 words, four dependent loads, one `br`) is therefore not where the near-tie cells lose; the ring cannot be paid for by anything it removes. A design with the same goal would have to make the push free
  (no push per call: the linked-call case is the common one, and a `bl`/`ret` pair with a real RAS entry needs the host `bl`, which the verifier forbids for the x30 clobber) or remove words elsewhere; not attempted.

### Product sketch (what a product version of (2) would have to change; (1) alone needs only the first three lines)

- **Contracts (docs/pipeline.md).** Section 2/4: the CFG pass gives a `BL`/`BLR` block its resume pc as successor and layout puts that block right after the call
  (nothing falls into it; every body PC is already an entry). Section 8: a `RET` exit whose target is no fragment's entry but a label in some fragment continues
  there and publishes the label (`kjit_lookup_label`, label hash under `kmm->lock`, cold path only); the profiler stops learning return points that a fragment already
  holds. Section 3: frame 464 bytes, ring at `[208, 464)`, cleared by the prologue; the lowering table above is the contract (push after the link write, pop between the target
  move and the template, a second budget check on the miss path).
- **Verifier rule 11 (ring groups).** The two exact groups; the push's `adr` target is an entry offset *and* `entry_pc(target) == the movz/movk constant that the
  call's link write leaves in x30` (needs `(offset, pc)` for the entries, which the kernel has in `kjit_entry`; the verifier input gains `entry_pcs`), so the pairing of pc and
  host is no longer the translator's; no join point inside a group; the pop guarded by a budget check; ring bytes `[208, 464)` reachable only through the groups (already
  true by rules 3 and 9). The mutation classes of this branch are the test list.
- **ABI cost** as above: +256 bytes of kernel stack per fragment call, +16 prologue words per call (about +49 words and one 256-byte clear per redis request), every
  fragment's offsets move; or the extra-params variant (+1 word per push and pop, no prologue change, a body-readable frame slot 184).
- **Risks.** (a) Code size: redis' fragments are 125 instead of 264-287 and their code 1.0-1.2 MB instead of 0.5-0.6 MB (each fragment holds the closure of its
  continuations, so a function body sits in every fragment that reaches it; the per-mm cap is 2 MiB and the arena chunk 2 MiB). (b) The FP/SIMD class is per fragment: a
  closure that reaches one FP/SIMD word makes the whole fragment FP/SIMD, and the transition into it is a runtime exit; the one transition per request moved from a BR exit
  to a RET exit and the BL/BLR transitions into FP fragments rose by about 0.1 per request. (c) Translation grows with the closure (`build_cfg` bookkeeping is quadratic; the
  per-translation caps of 16 pages and 16384 reads are hit sooner). (d) Every `RET` after a fragment call boundary (3 per request here: two syscalls and the FP bracket entry)
  starts with an empty ring and pays the 7 words of a miss. (e) A ring hit can enter a fragment that was retired during the call: it runs until its next dispatch, as a loaded slot
  or a linked `b` does. (f) A20 makes a linked `BL` 4 words shorter, so the push's 5 words are a larger share of it.

### Not verified

- The ring hit rate is derived (units(m2) - units(m1), assuming both modes execute the same transfers); no counter in fragment code counts hits or misses. Where the misses are
  (fragment-call boundaries, aliasing, mismatched returns) was not split; ring depth (16), the index (user sp[7:4]) and the extra-params variant were not swept or built.
- Why the pop earns nothing back (no PMU in the guest): branch-prediction and dependency-chain explanations are not measured; the push-only ablation (three boots, CIs through 0) only says the cost sits in the pushes.
- (1)'s time effect is inside the noise of this host (absolute levels 0.4-0.8 us above 07:53's, other agent's runs around my boots); more boots would narrow TCP GET (-0.040, CI upper -0.003) and SET (-0.065).
- The K3 suite, the redis campaign and the debug kernel were not run in modes 1-3; K2 only, where `fork_cow` fails in modes 1, 2, 3 (cause not investigated; the mode 0 control is K2 ALL PASS in mode 0 with the same module). `rmmod`/`insmod` inside the suites resets the mode to 0.
- KPTI off: only unix GET and SET, three boots. TCP cells and the other KPTI-off cells of 07:53 were not run. The `-c 1`, `-c 10`, AOF and pipelined cells (where K is small or the gap is large) were not run.
- Verifier product rule (pc of the `adr` target equals the link-write constant) is not implemented; the mutation suite proves safety rules only. The harness differential proves exactness of the cases above, not of every call shape.
- A20 (feat/a20-paths, not merged) shortens a linked `BL` by 4 words and removes SP checks; the ring's +5 per call would be a larger share there. Not measured.
- `make fuzz` ran 5000 programs per mode with its default shape, which has few calls and returns.
- Signals, ptrace and a multithreaded server with the ring were not exercised beyond the K2 cases that ran before `fork_cow`.
