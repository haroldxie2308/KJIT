### Implemented

- `spec/arm64/subset.toml`: 124 exact forms (112 single/double scalar FP: FADD..FMINNM, FMADD family, FABS/FNEG/FSQRT, FRINT*, FCVT S<->D,
  FCMP/FCMPE reg+zero, FCCMP/FCCMPE, FCSEL, FMOV imm, SCVTF/UCVTF, ten FCVT*; 12 LDR/STR (register, SIMD&FP) b/bl/h/s/d/q) and two MRS instances (FPCR,
  FPSR). `make spec-gen` (707 forms), generated files and the harness copy in sync.
- `shared/arm64`: `A64FpSimdMem.index` (`A64FpSimdIndex`), `fpsimd_mem()` for the register-offset forms (access = the same-size `#0` form),
  `option<1> == 0` undefined rule, `uses_fpsimd_state()`.
- `shared/trans/reg_virt.rs`: register-offset forms are window accesses; `add sA, <mapped Rn>, <mapped Rm>, <extend> #shift` (ADD extended),
  range check, base-only access; SP base gets the alignment check. Register-only forms are copied, GPR operands mapped.
- `shared/verify`: the 112 FP forms and MRS FPCR/FPSR are `Form::Simd` (`uses_fpsimd`); the 12 register-offset encodings are `UserOnly`; the lowering is
  accepted by rule 8 unchanged.
- Harness: `fp.rs` (every FP form on the host CPU with inline asm: state FPCR written, FPSR/NZCV read back, host FPCR/FPSR restored; `compile_error!`
  off aarch64; FCSEL, the FCCMP condition and FMOV-immediate expansion are integer code), register-offset addressing in `simd.rs`, MRS FPCR/FPSR,
  pretty printer, 199 encoding cases, `tests/arm64/fp_scalar.s` (32 `_mark` cases), fuzzer FP corner-case lane values, new unit tests and two
  mutation classes.
- Kernel: `kjit_call_fragment_fpsimd()` returns false (nothing run) when `thread.uw` FPCR has a trap-enable bit (8-12, 15); `runtime/exec.rs` handles it
  at any entry; stat `fpsimd_trap_declined`; `tests/guest/fp_trap.c` in `run-k2.sh`.

### Decisions not in the contract

- FCMP/FCMPE-against-zero pin their should-be-zero `Rm` to 0 (as SMULH `Ra`).
- MRS FPCR/FPSR set `uses_fpsimd`: outside the bracket the hardware registers are not the user's.
- A declined run: `kernel_neon_end()` only (nothing was written to `thread.uw`, no `fpsimd_cpu` invalidation needed). `run_chain` keeps
  `resume_pc` (entry pc, then each chained target) and sets `regs->pc` to it. A declined run counts `run_declined` and `fpsimd_trap_declined`, not
  `fragment_entries`/`fpsimd_entries`; a first-entry decline is not recorded in the chain histogram. FFI: `kjit_call_fragment_fpsimd(.., u64 *status) -> bool`.
- A fixture cannot write FPCR (`msr fpcr` is Unsupported): a case symbol with `_fpcr<HEX>_` starts with that FPCR (`case_state`, `check-case` takes the symbol).
- `FPCR_USER_BITS` comment: the "RAZ/WI" claim was wrong here: the trap-enable bits read back as written on the HVF guest and in the Docker VM (never trap).
- The fuzzer's minimizer still cannot lift a state with FPCR/FPSR != default into a fixture.

### Conclusion

- The Unsupported exits of the event loop and the AOF path are gone (0.05-0.11 and 1.0 per request to about 1e-5), and every syscall of the AOF cells now runs in the kernel
  (K 1.18 -> 2.18: the hook sees only 2.18 syscalls per request there, not 4).
- A18 costs 0.14-0.24 us less than main for -d 1 SET/GET (3/3 boots), 0.135 for -d 1024 SET, nothing measurable for -d 1024 GET.
  **KJIT on still does not beat off in any cell** (+0.30 to +0.49 us, 3/3 boots each).
- AOF `always` over unix: no gain against main (+0.06, noise +-0.2), still +1.05 above off. With KJIT on the run takes longer and the other CPUs receive 3.8x the IPIs
  (11.3k against 3.0k per 300000 requests). The sweep's "+1 us per Unsupported exit" explanation does not hold: the exit is gone and the gap stays. Not explained.
- unix SET without AOF: a18 is +0.10 above off where main was +0.01 (3 boots; within the noise of this host).

### Not verified

- The decline path against a CPU whose FP exceptions really trap (the HVF guest keeps the trap bits but never traps).
- A hardware oracle other than Apple M-series (native suite and host interpreter).
- Why the AOF gap stays at +1 us; why unix SET without AOF is slightly worse with a18.
- A 16 KiB-page kernel, `rodata=full`, measurements at other KPTI settings or with more than 3 boots.
