## 04:15 +0800 — ROX vs RWX fragment images

Commit: e3b6e65 (branch `exp/rox-rwx`, experiment-only, not merged)

Data: `docs/data/2026-10-12/0415-rox-rwx.csv` (one row per measured run), `-pairs.csv`, `-kb.csv`, `-place.csv`, `-ptes.csv`,
`-linear-map.csv`, `-install.csv`; raw logs in `docs/data/2026-10-12/0415-rox-rwx/<boot>/`.

Question: 22:37 found the same module costing 0.19-0.32 us more server CPU per redis request with ROX images (`set_memory_rox`, main's
install) than with RWX ones (`set_memory_x`), across boots, on the pre-A15 tree. Does it reproduce within a boot on main (A15)? What is
the mechanism? What keeps W^X and costs less?

### Answer

- **The ROX-vs-RWX attribute difference is not the cost.** Paired inside one boot (17 boots), ROX - RWX is +0.03..+0.055 us per request
  (median; quartiles about -0.1..+0.25), the same as the noise floor of installing the *same* mode twice (rox - roxb, rwx - rwxb:
  -0.09..+0.09 per cell). The 0.19-0.32 of 22:37 is inside the boot-to-boot spread of a reinstall (per-boot medians of rox - roxb run
  -0.16..+0.39 us), and 22:37 compared 4 boots with 6. I could not reproduce a 0.2-0.3 gap.
- **What does cost is where the images sit.** The page-granular images (one execmem allocation each, vmalloc with a guard page) leave the
  L1I set-index bits above the page offset, VA[14:12], to vmalloc. A14 colours only VA[11:6]. The VA[14:12] histogram of the images in
  a boot is far from uniform (e.g. 17 40 20 38 20 96 27 37; the 8-bin imbalance is 1.32 on average where 1.0 is uniform). Choosing the
  image's page so that VA[14:12] is uniform recovers 0.3-0.6 us per request; packing the images densely into shared ROX chunks recovers
  0.75-1.1 us (10 of 10 boots), i.e. KJIT's overhead over KJIT-off drops from 1.4-1.8 to 0.6-0.8 us per request. The mechanism is
  **inferred** from the dose-response (rox < va2 < va8 < arena, imbalance 1.32 / 1.20 / 1.00 / 1.01); there is no PMU in the guest.
- **No linear-map effect.** No split happens at runtime in either boot configuration (the linear map's leaf counts are identical in every dump within a
  boot, 721 dumps in all), kernel micro-benchmarks are the same with ROX and RWX images installed, and `rodata` full vs off does not change
  ROX - RWX.

### Method

Module `exp/rox-rwx` (kjit_glue.c, all marked EXPERIMENT; debugfs `exp_img` bit mask, `exp_perm`, `exp_lm`, `exp_ptes`, `exp_insn_copy`).
`exp_img` changes only with KJIT disabled, drops every fragment of every mm (seq++, retire, hook-SRCU barrier, `rcu_barrier`, flush of the
free workqueue) and refuses (-EBUSY) if one is left, so modes pair within a boot like attrib_pan_run of exp/pan-sweep.
Modes (all with A14 colour and A15 unless stated): `rox` = main; `rwx` = `set_memory_x` only; `roxb`/`rwxb` = the same, under another
name, so every change of name reinstalls (a placement control); `roxnc`/`rwxnc` = colour offset 0; `va2` / `va8` = the image starts on a page
of the allocation chosen so that VA[12] / VA[14:12] cycle (allocation + 1 / + 7 spare pages); `arena` = images bump-allocated at 16 B in
2 MiB execmem chunks made ROX once and written through `aarch64_insn_copy` (the symbol is not exported: the host passes its address from
`System.map`, the kernel is nokaslr; a product needs the export, kernel patch 0008).
Protocol: `tests/guest/rox-sweep.sh` (ub-standard.sh protocol: kjit-guest 4 vCPUs M1/HVF, KPTI off, server on CPU 0, `redis-benchmark -t
set|get -n 1000000 -d SIZE --threads 2 -q` on CPUs 1-3, sizes 1 and 1024, server CPU = (utime+stime)/CLK_TCK/requests, 10 ms ticks), per rep
`off` first then the modes in a rotating order, 300000 SET + GET warm-up after each switch, then after each measured pair (KJIT disabled)
`svc_bench` null syscall / pipe / read+write on CPU 1 with the fragments still installed, and a page-table dump. Command line
`rodata=off` (the UB protocol's) except campaign e. Statistics: per (boot, size, test, rep) difference of two modes inside the pass;
quartiles over all passes; "x/y" = boots with a positive per-boot median.

### Evidence for the mechanism, and against the candidates

- **Linear alias.** With the UB command line (`rodata=off`: `rodata_full` false, so `set_memory_ro` skips the linear alias) all 295 / 320
  fragments' linear aliases stay block-mapped and RW; with the default (`rodata=full`) the linear map is page-granular from boot
  (1047040 4 KiB leaves, 3 2 MiB leaves for the image) and the aliases are RO for ROX, RW for RWX. In both the leaf counts of the whole
  linear map (`exp_lm`: 1G / 2M / 2M-cont / 4K / 4K-cont walked from TTBR1) are identical in every dump within each boot (721 dumps): no
  split, no change. Source: `can_set_direct_map()`/`change_memory_common()` in arch/arm64/mm/pageattr.c only touch the alias when
  `rodata_full`, and `split_kernel_leaf_mapping()` (this 7.1 kernel's runtime splitter) is only called on the range being changed, which is a vmalloc range.
- **Kernel-wide cost.** With fragments installed and KJIT disabled, `svc_bench` ns per syscall, medians over 88-168 samples:
  getppid 132.0 (rox) / 132.1 (rwx) / 130.5 (off); pipe 168.2 / 168.5 / 167.9; read+write 148.2 / 148.5 / 148.0. Default `rodata`: 127.9 / 127.5 /
  126.2, 160.3 / 159.9 / 159.6, 146.1 / 145.8 / 145.4. ROX = RWX within 0.3 ns.
- **Install cost.** `set_memory_rox` 80 us, `set_memory_x` 79 us (the instrumented step, per image), arena copy through the text-poke path 79 us,
  about 300 images per switch; irrelevant in steady state (campaign a: translate_ok 0 in 280 of 288 measured runs, 1 in 8).
- **PTE bits.** The vmalloc PTEs are `RDONLY` + no `DBM` for ROX and `DBM` + writable for RWX in all dumps (`exp_ptes`); the cost is the
  same, so neither bit matters. (The DBM-flip modes `roxd`/`rwxd` exist in the module but were not run: there was no effect to isolate.)
- **Placement.** Imbalance of the images' VA[14:12] histogram, rox 1.32, va2 1.20, va8 1.00, arena 1.01 (mean of 80 dumps each), against
  the gap above off 1.59, 1.41, 1.14, 0.72. Across the three page-granular modes the correlation of imbalance and gap is 0.54; within rox
  alone 0.17-0.20 (n = 80), so the imbalance explains part of the spread between modes and little inside one. `va8 - arena` (0.1-0.5) is
  not VA uniformity: arena also halves the page count (about 160 instead of 295-320 pages) and gets physically contiguous chunk pages
  (the pfn histogram of an arena chunk is its VA histogram shifted); I did not separate those.

### Options (all keep W^X; measured against main's ROX install)

1. **Packed ROX arena** (the prototype above): 0.75-1.15 us per request, 10 of 10 boots; memory about half (645 KB per 296 fragments, no
   per-image page rounding). Cost: **kernel patch 0008** exporting `aarch64_insn_copy` (the BPF prog pack's arm64 writer, fixmap alias under
   `patch_lock`; a second export `aarch64_insn_set` to poison freed slots); a chunk/slot allocator (free list per chunk, return a slot after the
   hook-SRCU grace period plus the poison, release an empty chunk); `docs/pipeline.md` section 8 changes ("image = one execmem allocation ...
   `set_memory_rox`" and "Image placement (A14)": colouring becomes unnecessary, caps count the real bytes); extable entries stay inside the
   slot (self-relative, found through the fragment list). The prototype leaks slots until `exp_img` changes and was not run through verifier
   stress, munmap, or unload tests. Writer path is EL1 code that writes into live executable pages: the new thing to audit.
2. **VA[14:12] spreading** (`va8`, no kernel change): 0.3-0.6 us; allocation + up to 7 pages (about 14 KB per fragment on average, 4 MiB for
   300 fragments); `va2` (+ at most one page) 0.04-0.26 us. Contract cost: one line in section 8 (the image start is chosen from VA[14:12],
   not only the 16 B colour), caps and the free keep covering the whole allocation. Core-specific (L1I 6-way, 32 KiB per way), as A14 is.
3. **Change nothing about permissions**: RWX is not a product option and there is nothing to gain from it (+0.03..0.055 us, noise).

Recommendation: ship option 1, with `va8` as the stop-gap if patch 0008 and the allocator are not wanted yet (it is 15 lines in
`kjit_install`, no new kernel surface). Do not spend more on the ROX/RWX difference.
