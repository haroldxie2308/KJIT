## 00:57 +0800 — Session recorder decided (TUI data layer)

Commit: 8fc95a6

Question: the trace TUI shows one fragment's passes and a lock-step of one
fragment run. It cannot show the JIT at work over a program (what turns hot,
what is translated, how runs move between fragments). Its interactive backend
also needs an OpenTUI dylib from outside the repo, which is absent here.

Decision: build one recorded, deterministic whole-program session as the
data layer, with a query API. Two TUI modes (debug, observe) on ratatui
consume it and add no model logic. The old explorer cluster is deleted.
Contract: docs/pipeline.md, "Session recorder (TUI data layer)".

Main points:
- The session models the syscall-return hook, the K3 profiler (hit counts
  only, no time window) and the kernel's miss behaviour (return to userspace
  and profile the target). The miss behaviour is a new `CodeCache` miss
  policy; the differential suite keeps translate-on-miss.
- A reference world (the original alone) is compared with the KJIT world at
  every SVC and at the end. The first mismatch is a recorded `Divergence`.
- Translation records rebuild every pass and must equal the installed code
  word for word.
- Steps are recorded as diffs with periodic checkpoints. Sessions are
  fixture-scale.

## 01:28 +0800 — Session recorder implemented

Commit: b2d9bff

Built to the contract in docs/pipeline.md, "Session recorder (TUI data layer)":
`harness/src/session/` (`Session::record`, the recorded translations, events and
steps with checkpoints, and `state_at`, `cache_at`, `events_between`, `origin`,
`words_for`, `reference_at_syscall`), `bin/session-dump` and `make session-dump`,
three session programs (`tests/arm64/session_{svc,call,indirect}_loop.s`, 300
iterations each, also fixture cases). The old explorer cluster, `libloading` and the
`harness-tui` targets are gone; `make harness-test-asm` now runs the new
`bin/check-case` (the differential check `trace-tui --check` made).

Hooks in existing code (no execution is re-implemented): `CodeCache` has a miss policy
(`Translate` default, `ReturnToUser` = `run_chain` of runtime/exec.rs: the entered
fragment's label, then the fragment translated for the target, else return and
profile; budget stops every branch exit; an SVC exit always returns) and an opt-in
event log; `MachineState` has a write journal outside its equality; `URuntime`
reports what a fragment returned with.

Model points that follow the kernel code, not the contract text: an SVC executed
inside a fragment ends the chain and starts a new hook call (budget reset); only a
fragment translated for exactly the pc is found by the hook's lookup; a request whose
entry word is unsupported or unreadable is refused and goes to the negative cache.
Not modeled: the uncounted first hit of an mm, the fragment/code caps, `kjit_can_run`
and a negative `x8`. The return to `SESSION_EXIT_PC` from a fragment is a miss like
any other and is profiled once.

Gates: `make harness-prepare && make harness-test` 294 passed (0 failed, 2
ignored; the fixture suites 136 cases across 42 fixtures); `make harness-test-native`
(linux/arm64 container) 297 passed. The session tests check: normal exit with no
divergence for all three programs; translation exactly at the hit threshold (1, 7,
64); no runtime transfer in the last 20 chains of the call programs; no `Linked`
event with links off; `cache_at(last)` equal to the final cache; `state_at(t)`
equal to a fresh run stopped at `t` across checkpoint boundaries; every step taking
the previous state to the next (checkpoint every tick); a tampered register or memory
word diverging at its syscall; faults and unsupported words halting both worlds.
