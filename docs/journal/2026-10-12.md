### Phase 1: shared, harness, module source, patch

  `nop` between a static `BL`'s link write and its template; reg-virt passes it
  through.
- `shared/emit/layout.rs`: `ExecutionFragment::link_sites: [(slot_offset,
  target_pc)]`, `LayoutError::MalformedLinkSlot` (not a `nop`, or no template
  directly after).
- `shared/abi/link.rs`: `link_branch_word(slot_addr, host) -> Option<u32>`
  (`None` out of +-128 MiB or unaligned) and `LINK_NOP_WORD`.
- `shared/verify`: `VerifyInput::link_sites`, `VerifyRule::LinkSite`, rule 10.
  A `nop` is now a legal word of the budget-to-template gap (it is the slot).

  kernel (install links own and pending sites, retire restores incoming sites),
  `drain_code_patches` for the native backend, `check_invariants` extended;
  `URuntime::new` (one fragment, never publishes) uses `without_links()`.
- `runtime/` and `kjit_glue.c`: `kjit_link_patch`, `struct kjit_link` allocated
  with the fragment, per-mm pending hash and label index (allocated with the

  gauges `link_sites_linked`/`link_sites_pending` in the stats file.

  Not applied to any tree; `git apply --check` against the patched tree passes.

### Phase 2: kernel, guest gates, race test, measurement

Kernel and modules (dev container, `KJIT_BUILD_ROOT=.kjit/build`): `make kernel-tree` (8 patches on the
pinned base; patches 0001-0007 keep their commit ids, 0008 is new), `make guest-kernel guest-kernel-debug`
(both kernels rebuilt in place, A16 module included, no warning). The module of the base commit cd54010
("main") was built from a git worktree of it against the same kernels (`make module-build
KJIT_MODULE_DIR=$B/mod-a16/main/<profile>`). md5: A16 `16a4528a` (kjit-guest), `527c86d9` (debug); main
`d1de28ff`, `367aea2e`. The main module needs no export, so both load on the new kernel.

Race test `tests/guest/bl_link_race.c` (ported idea of the experiment's `dab_bl_race.c`; registered in
`run-k2.sh`, so it runs in K2 and, with the auto mode, in K3): 3 callers loop `bl callee; getpid` in their
own text page while one thread flips the callee page (exec-only <-> read-exec, `MADV_DONTNEED`) and the
caller page, each change followed by a new translation (not in auto mode); then the callee is rewritten in
place. Output is identical with KJIT on and off. With `KJIT_EXPECT=bl_link` it requires links made and
restored during the storm and a linked site afterwards. Seen: `link_made` 1694-2048, `link_restored`
1130-1366 per run, no wrong sum; after the process exits `link_sites_linked` and `link_sites_pending` are 0.

Gates (`make guest-tests`, `guest-tests-k3`, `redis-campaign K4_ARGS=--no-suite`, both profiles, the
default A16 module): all six exit 0 (`k2: ALL PASS`, `k3: ALL PASS` with `unload_stress` PASS, campaign
`RESULT PASS`, consistency PASS, `translated=512`). No `BUG`, `WARNING`, `KASAN`, `Oops`, `sleeping function`,
`Call trace`, `lockdep` splat, soft lockup or RCU stall line in any serial log or campaign dmesg (the only match is the
boot banner "RCU lockdep checking is enabled" of the debug profile); "Privileged Access Never" detected in every boot.
