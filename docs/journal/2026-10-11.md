## 00:37 +0800 — Merged main (A12 + A13): code speed and redis

Commit: b80997d

Question: how fast is the merged tree, with the register budget counter and
the preemptible FP/SIMD bracket together?

Method: kjit-guest, build root `.kjit/build`, kernel with the new patch 0005.
- Code speed: `tests/guest/host/ub-run.sh main-codeN 0 'sh
  /opt/kjit-tests/ub-bench.sh code 7'`, 2 boots.
- Redis: `ub-run.sh main-redisN 0 'sh /opt/kjit-tests/a11-baseline.sh /tmp/a11
  3 200000 off 1024'`, 3 boots x 3 passes.
- Host load1 at boot start: 3.2-5.7.

Data: [code speed](../data/2026-10-11/0037-main-code-speed.csv), [redis](../data/2026-10-11/0037-main-redis.csv); raw logs in the directories of the same names.

Results:

Code speed (`ub-summarize.py code`; the slope is ns per unit of n, the
intercept is ns per outer iteration, i.e. per syscall):

| variant | off slope | on slope | slope ratio | off intercept | on intercept |
|---|---|---|---|---|---|
| strlen | 0.319 | 0.319 | 1.00 | 142 | 65 |
| copy | 0.320 | 0.324 | 1.02 | 137 | 57 |
| hash | 0.960 | 0.955 | 1.00 | 128 | 46 |
| copy16 | 0.0244 | 0.0361 | 1.48 | 124 | 48 |
| calls | 1.530 | 2.310 | 1.51 | 112 | 58 |
| calls2 | 2.473 | 4.419 | 1.79 | 106 | 48 |
| simd32 | 0.0137 | 0.489 | 35.8 | 124 | 100 |

Redis (median of 9 runs each; KJIT on means chain_budget 1024):

| | off req/s | on req/s | on/off | runtime entries/req |
|---|---|---|---|---|
| SET | 238379 | 145033 | 0.608 | 3.04 |
| GET | 240385 | 166945 | 0.694 | 3.04 |

Conclusion:
- Byte loops (strlen, copy, hash) now run at native speed per byte.
- Every syscall that resumes in a fragment saves about 75-80 ns of per-call
  constant (intercept 46-65 ns against 106-142 ns).
- Calls cost about 1.5x native per call (the dispatch sequence).
- SIMD q-register copies cost 36x native (one PAN window per access).
- Redis is unchanged at about 0.61/0.69 of native. With 3 runtime entries per
  request and native-speed integer loops, the remaining loss is not explained by
  these micro-benchmarks. Not yet attributed.
